# 🔥 Homeostatic Heater

[English version](README.md)

Обогреватель на угле и лаве для Minecraft Fabric 1.20.1. Он согревает игроков через
датапак-систему теплового излучения Homeostatic без mixin, изменения чужого
мода или преобразования сохранения мира.

[Скачать последнюю версию](https://github.com/sqwiziiy/Homeostatic-Heater/releases/latest) ·
[Установка](#установка) · [Проверка в игре](TESTING_RU.md) ·
[История изменений](CHANGELOG_RU.md)

## Что умеет

- Греет игроков, пока работает, с учётом радиуса и преград Homeostatic.
- При **Shift + наведении на установленный блок** показывает оставшееся время
  в минутах и секундах, **Неактивен** или **Работает постоянно**. Состояние и
  время вычисляет сервер; клиент только показывает синхронизированный ответ.
- Даёт достижение **«Отоплительный сезон»** с иконкой костра за крафт.
- Принимает **одно ведро лавы** и возвращает пустое; лава горит дольше угля.
- Включается и выключается ПКМ пустой основной рукой, сохраняя запас топлива.
- Позволяет настроить время горения угля и лавы, запас угля и режим без расхода топлива.
- Имеет объёмную модель предмета, спокойную анимацию огня, звук зажигания,
  редкое потрескивание и небольшой дым сверху во время работы.

## Использование

Обогреватель находится во вкладке **«Функциональные блоки»**.
Можно выдать командой `/give @s homeostatic_heater:coal_heater`.

- ПКМ с углём или древесным углём: 1 кусок горит **80 секунд** по умолчанию,
  запас — до 16 кусков, включая горящий.
- ПКМ с **ведром лавы**: принимается максимум **одно ведро** (горящее или
  ожидающее), возвращается пустое ведро. По умолчанию лава горит
  **16 минут 40 секунд**. При заполнении второй лавой ничего не тратится.
- Уголь и лава могут храниться вместе. Если ожидает лава, она сгорает
  следующей после текущего топлива, затем продолжает гореть уголь.
- **ПКМ пустой основной рукой:** включить/выключить. В выключенном состоянии
  уголь и лава **не тратятся**, тепло, свет и дым прекращаются. Включение
  продолжает горение с оставшегося времени.
- **Shift + прицел:** показывает время и состояние; при выключении —
  «Выключен» с остатком топлива.

Управление полностью серверное; клиент не может прибавить себе топливо или
тепло. Сломанный блок выпадает, **неиспользованное топливо не возвращается**.
Режим Creative не тратит предметы. Старые блоки и сохранения совместимы.

## Конфиг сервера

В `config/homeostatic_heater.json` на **сервере** после первого запуска:

```json
{
  "burn_ticks_per_coal": 1600,
  "burn_ticks_per_lava": 20000,
  "max_coal": 16,
  "always_active": false
}
```

| Параметр | По умолчанию | Значение |
| --- | ---: | --- |
| `burn_ticks_per_coal` | `1600` | Время угля/древесного угля |
| `burn_ticks_per_lava` | `20000` | Время одного ведра лавы |
| `max_coal` | `16` | Количество угля, независимо от лавы |
| `always_active` | `false` | Бесплатный нагрев, если прибор включён вручную |

20 тиков = 1 секунда. Время горения — от 1 до 1 728 000 тиков,
`max_coal` — от 1 до 64. После изменения нужен перезапуск сервера.
Старый конфиг без параметра лавы работает с значением 20000, файл не
перезаписывается. При ошибке чтения применяются значения по умолчанию
с предупреждением. Старые сохранения топлива сохраняются; при переходе
в `always_active` топливо не расходуется. Клиентский конфиг не влияет
на сервер.

## Сила обогрева в Homeostatic

Встроенная запись датапака задаёт работающему блоку
`max_radiation: 8325.0` — как у включённой горелки Create в Homeostatic.
Homeostatic 1.20.1 проверяет блоки лишь в пределах 12 блоков по горизонтали
и 3 блоков выше игрока. Для большой виллы поставьте несколько обогревателей;
стены и расстояние продолжают влиять на тепло.

Для изменения силы используйте [`server-config-datapack/`](server-config-datapack/):
заархивируйте **содержимое** папки, положите zip в `<мир>/datapacks/` и
выполните `/reload`. В релизе также есть готовый zip для правки. Повышение
`max_radiation` не расширяет радиус поиска Homeostatic.

## Установка

1. Установите Fabric Loader для Minecraft 1.20.1 и Fabric API на сервер и
   каждому игроку.
2. Установите совместимую версию Homeostatic 1.20.1 **на сервере и клиентах**.
   Это обязательная зависимость.
3. Удалите старые jar обогревателя и положите новый jar из релиза в `mods/`
   сервера и каждого клиента. Оставьте только одну версию.
4. Сделайте резервную копию мира, запустите сервер и проверьте мод по
   [чек-листу](TESTING_RU.md).

Fabric mod ID — `homeostatic_heater`, пакет Java —
`com.mentality.homeostatic_heater`. Старые ID `mentality_heater` и
`stormheater` сохранены, чтобы ранее установленные блоки и предметы не исчезли.

## Сборка и проверка

Компилируйте на JDK 17, даже если сервер запускается на более новой Java:

```sh
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk
./gradlew build
```

Готовый файл: `build/libs/homeostatic-heater-1.6.0.jar`. GitHub Actions
проверяет JSON, запускает Java-тесты, собирает jar на Java 17 и выкладывает
сборочный артефакт. Рендеринг, частицы, звук, крафт и нагрев от Homeostatic
нужно проверить вручную по [чек-листу](TESTING_RU.md).

## Автопубликация на Modrinth

При публикации нового **GitHub Release** workflow собирает jar именно из
тега релиза, запускает тесты и отправляет файл на Modrinth. Для включения
добавьте Secret и Variable согласно [PUBLISHING.md](PUBLISHING.md).
Пока их нет, сборка проходит, но загрузка **пропускается**. Для уже
опубликованного GitHub Release можно вручную запустить workflow с его тегом.
